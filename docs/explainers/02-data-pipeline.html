02 · Data Pipeline

Simulator → teacher → quality gate → dataset — 3 July 2026

Shape of the pipeline

simulate ──▶ generate ──▶ judge ──▶ filter ──▶ train.jsonl
 (seeded)    (teacher LLM)  (rubric)   (rules+dedup+balance)

Every stage reads and writes JSONL, so any stage can be inspected, rerun, or resumed independently. Teacher calls checkpoint after every record — an interrupted overnight run loses nothing.

Decision

Scenarios are simulated programmatically, not asked from an LLM

A 15-cell safety taxonomy (drowsiness episodes, gaze-off-road × speed, phone use, child distraction, alert fatigue, false-positive traps…) with seeded samplers gives guaranteed, stratified coverage — including the rare critical cases an LLM asked to "imagine driving scenarios" reliably under-samples. It's also deterministic: the same seed yields byte-identical scenarios on any machine, so the Kaggle GPU kernel regenerates them instead of shipping files around.

Rejected: LLM-generated scenarios. Coverage becomes a vibe, not a property; duplicates and mode collapse near the taxonomy tails; non-reproducible.

Decision

Each taxonomy cell carries a ground-truth severity band

Unambiguous cells pin the response (microsleep at highway speed ⇒ exactly critical); ambiguous cells allow a range (a lone high eye-closure reading with zero corroboration ⇒ none…caution) so the teacher may exercise judgment. The band is never shown to any model — it powers the hard reject in data generation and the severity-accuracy metric in eval.

Decision

Behavioural constraints live in code, not in the schema

CoachResponse validates structure (enums, types, length caps). Eight deterministic safety rules — "critical ⇒ ≤ 8 words and an alarm action", "phone-in-hand while moving may never be under-called", "≥ 3 recent alerts ⇒ suppress low-severity nudges", "never direct the driver to a screen while moving" — are plain Python over (scenario, response) pairs. Two payoffs: they hard-gate training data and they are the safety-compliance metric at eval, measured independently of schema validity.

Decision

Teacher prompt is long; student prompt is 60 tokens

The teacher system prompt (~1,200 tokens) encodes signal semantics, the severity policy, voice rules, and three few-shot examples. Training pairs are written in chat format with the short student prompt, so the model learns to behave as if the long prompt were present. This gap is the measurable thesis of the project.

Decision

Dedup and class balance run before anything reaches training

Near-duplicate coaching messages (normalised text, per severity class) are dropped — small models memorise stock phrases fast, and message variety is a rubric criterion. Severity classes are capped at 2.5× the smallest class so none-severity examples (the most common cells) can't drown out critical ones.
