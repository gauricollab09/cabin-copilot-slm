The human runbook — three things, once

  1. Create the Kaggle API token. kaggle.com → avatar → Settings → API → Create New Token. Leave the downloaded kaggle.json in Downloads — a watcher picks it up within a minute. This is the single hard blocker; no paid account needed.
  2. Verify a phone number on the Kaggle account (same Settings page) — Kaggle gates GPU kernels behind phone verification. ~30 GPU-hours/week free, this project needs a fraction of that.
  3. Keep the laptop plugged in, lid open until the fallback generation finishes (~4 h from the snapshot). caffeinate blocks idle sleep but cannot survive a closed lid.

What happens automatically, and when

When the fallback generation completes (~4 h)

cabin-copilot filter --raw data/raw/train_ollama.jsonl --out data/dataset
# → data/dataset/train.jsonl, the fallback training set (hinted 3B teacher)

This dataset trains a real model even if the 14B path never runs — lower ceiling, same pipeline.

Decision points ahead

Fork

Which dataset trains the shipped model?

If the 14B teacher runs: its dataset is preferred — explainer 02 showed small teachers parrot few-shot phrasing even when hinted. If Kaggle GPU access stalls: the fallback llama3.2 dataset trains the same config unchanged. Either way the eval harness, not the narrative, decides whether the result clears the 55.3%-safety / 5.6 s-latency bar the baselines set. A third option — training on both and comparing — costs one extra T4 run and would measure teacher quality directly; worth it if GPU quota allows.

Risk

Known risks, with mitigations already in place

Training script has never executed end-to-end (needs CUDA): contained — everything around it is rehearsed, so a first-run failure costs minutes. Kaggle 12-hour kernel limit: irrelevant at this scale (~2,000 samples × 2 epochs on a 3B ≈ well under 2 h on a T4). Fallback dataset class skew if the run dies early again: caffeinate + resumability mitigate; the filter's balancer handles the rest. 16 GB RAM ceiling locally: generation and eval are sequenced, never two models resident at once (the stand-in demo reuses the already-loaded base).

Definition of done

  • Results table shows all three rows, measured on this laptop through Ollama.
  • The fine-tuned row beats baseline (c) on safety compliance at baseline (b) latency — or the README says plainly that it didn't, and by how much.
  • ollama run cabin-copilot '<signals json>' works on-device; /coach serves it; the eval and demo are reproducible from the repo with any of the five teacher backends.
  • PR #1 merged with the full explainer trail (01–07) as the build log.
