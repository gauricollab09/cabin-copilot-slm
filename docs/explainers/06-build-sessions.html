06 · The build sessions

A detailed log of what was thought, tried, and done — session by session. July 3–4, 2026.

Explainers 01–05 document the design decisions. This page documents the build itself: the actual sequence of work, the failures along the way, and the reasoning at each fork. It exists because "how it was actually built" is a different story from "how it was designed" — and usually a more honest one.

Finding

The 3B teacher mis-calibrated severity on 77% of samples

The first local generation run (llama3.2, no hints) passed the quality gate only ~10% of the time — almost entirely severity mis-calibration, not schema failures. The fix was label-conditioned generation (--hint-band): the teacher sees the simulator's ground-truth severity band; the student never does (training pairs contain raw signals only). Acceptance jumped to ~85%+. The A/B also surfaced the counter-finding: even hinted, small teachers parrot few-shot phrasing — the measured argument for the 14B-teacher Kaggle path. Details in explainer 02.

The session ended with the hinted llama3.2 fallback run in flight (98%+ parse success) and one external dependency outstanding: a Kaggle API token, which only a human can create. At 01:21, at 508/2,400 samples, the laptop went to sleep and killed the run. Nothing was lost — the generator's append-and-skip design is exactly for this — but ~6 hours of generation, one baseline eval, and explainer 04 were left stranded and uncommitted.

Session 2 — July 4, morning (resume, de-risk, dress-rehearse)

1 · Reconstructing state

The session began by locating the project (searching the machine for QLoRA/RAG/LoRA work from the previous day), then reconstructing exact state from three sources: the git log (5 commits, clean tree except two untracked paths), the generation log (dead at 508/2,400), and the previous session's transcript — which yielded the exact relaunch command, including --hint-band --temperature 0.8. Resuming with a different command would have silently produced a mixed-distribution dataset; recovering the verbatim invocation was the whole point of reading the transcript.

Decision

Resume, don't restart — and pin the laptop awake

The 508 completed samples were generated under identical settings, so resume was a pure win: the CLI skips done scenario IDs and appends. Post-resume failure count: zero. To prevent a repeat of the 01:21 death, caffeinate now holds the machine awake for the rest of the run.

Rejected: sharding generation across parallel workers. A 3B model through Ollama on an 8-core Intel i9 is compute-bound; parallel requests share the same cores and buy little except memory pressure on a 16 GB machine already running an eval.

2 · Resource inventory — what can actually run where

Before promising anything, the machine was audited: 2019 MacBook Pro, 8-core Intel i9-9880H, 16 GB RAM, no CUDA, no Apple-Silicon MPS — and a sweep of shell configs, environment, and credential caches found no API keys of any kind (no Anthropic, OpenAI, Groq, HuggingFace, or Kaggle). Consequences: the teacher for the fallback dataset must be local Ollama; the strong 14B-teacher path and all GPU training have exactly one free route — Kaggle — and its token is the single human dependency. Training on this laptop was ruled out twice over: infeasible (days on CPU, bitsandbytes needs CUDA) and explicitly excluded by the project owner.

3 · Landing the stranded work

The interrupted session had produced baseline (b) — base 3B + 60-token student prompt: 20% schema-pass, 10.7% safety compliance, 11.3% severity-in-band (n=150, p50 5.6 s) — and a finished explainer 04. Both were committed, the README results table gained its first measured row, and baseline (c) — base 3B + full 1,200-token teacher prompt — was launched in the background, since it depends only on the base model and the eval set (see the "baselines run before training finishes" decision in explainer 04).

4 · Removing every obstacle between "token appears" and "training runs"

So that the one human action unblocks everything with zero further friction: a filesystem watcher now fires the moment kaggle.json appears in ~/.kaggle/ or ~/Downloads; the Kaggle CLI (2.2.3) is pre-installed in the project venv; both kernel scripts compile clean and their metadata is validated; the test suite (35 tests) and lint pass; and draft PR #1 is open so every subsequent push is reviewable.

5 · The dress rehearsal — simulate everything that can't run for real yet

The stages downstream of training (filter → export → demo → serve) would normally be exercised for the first time after a multi-hour GPU run — the worst possible moment to discover a bug. Instead, each was run now with a stand-in:

StageStand-in usedResult
Quality filterThe 574 raw samples generated so far Works — dedup, balancing, severity/taxonomy stats produced (data/dryrun/)
Export → Ollama democabin-copilot-dryrun: base Qwen2.5-3B wrapped in the exact production Modelfile (same template, system prompt, stop tokens) Works — answers in the JSON contract; real GGUF becomes a one-line swap
FastAPI servingSame stand-in via CABIN_MODEL Works — and the failure path proved itself: the base model dropped a required field and the contract validator correctly returned 502 rather than passing garbage
Kaggle kernelsStatic checks (compile + metadata) Clean — cannot be executed further without the token
Decision

Stand-in model over a tiny local training smoke-test

A "train a toy model for 5 steps on CPU" smoke-test would validate the training script's wiring, but the script's core path is 4-bit bitsandbytes quantization, which requires CUDA — a CPU variant would test a different code path while installing ~3 GB of dependencies, and would brush against the owner's explicit "no training on my machine" constraint. The stand-in approach tests everything downstream of training against the real serving stack instead; the training script itself gets its shakedown on the first Kaggle run, where its failure costs minutes, not hours, because everything around it is already proven.

6 · Baseline (c) landed — and completed the argument

Base 3B with the full teacher prompt: 100% schema-pass but only 55.3% safety compliance, at +54% median latency (8.6 s vs 5.6 s). Together the two baselines are the project's thesis in numbers: prompting buys format, not judgment, and pays 1,200 prompt tokens on every call. The fine-tune's target is now precise — teacher-prompt behaviour (≥55% safety, ideally far above) at student-prompt latency.

Honest ledger

  • Lost: ~7 hours of overnight generation time to laptop sleep — a process-supervision failure, now mitigated with caffeinate.
  • Unproven: the training script end-to-end and the 14B-teacher kernel — both gated on the Kaggle token, both deliberately left for the first cloud run with everything around them de-risked.
  • Known skew: the dry-run filter output over-represents benign cells (the generator walks scenarios in order); the real filter run happens on the complete 2,400.
