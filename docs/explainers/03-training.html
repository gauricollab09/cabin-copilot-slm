03 · QLoRA Training

Free-GPU orchestration and hyperparameter reasoning — July 2026

Decision

QLoRA on a free Kaggle T4, driven headlessly from the laptop

The build machine (2019 Intel MacBook) has no usable training GPU. Kaggle gives 30 GPU-hours/week free and — unlike Colab — has a real CLI (kaggle kernels push/status/output), so the whole train job is scripted and reproducible instead of clicked. The kernel clones this public repo, so the only artifact shipped to Kaggle is a dataset; everything else is code under version control.

Rejected: Colab — interactive-only, no honest headless story. Rejected: paid GPU clouds — the project's constraint is $0 infrastructure, and a T4 is genuinely enough for a 3B QLoRA.

Decision

Hyperparameters: the boring, defensible recipe

ChoiceValueWhy
Quantization4-bit NF4, double-quant, fp16 compute Standard QLoRA; fp16 not bf16 because the T4 (sm_75) has no bfloat16.
LoRA rank / α16 / 32 The task is narrow and highly structured; rank 16 over all attention+MLP projections is ample capacity. Bigger ranks mostly buy overfitting here.
Epochs2 Small dataset of short, formulaic targets — loss plateaus fast; more epochs means memorising teacher phrasing verbatim.
Effective batch16 (2 × grad-accum 8) What fits a 16 GB T4 at seq-len 1024 with gradient checkpointing.
LR2e-4, cosine, 3% warmupCanonical QLoRA LR for adapters.
Optimizerpaged_adamw_8bitHalves optimizer VRAM; standard with bitsandbytes.

All of it lives in training/configs/qlora_qwen25_3b.yaml; the run snapshots the config next to its outputs so no result is ever orphaned from its settings.

Decision

Training on chat-format JSONL with the short student prompt

Every example is system(60-token student prompt) → user(signals JSON) → assistant(contract JSON). The long teacher prompt appears nowhere in training — its behaviour must be carried entirely by the examples, which is the point.
